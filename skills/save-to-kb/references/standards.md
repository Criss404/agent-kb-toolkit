# 知识库记录规范(standards)

写入知识库的每篇笔记必须遵循以下 6 节规范。

## 1. 内容类型:Diátaxis 四象限

每篇笔记只属于一种类型,在 frontmatter 声明,禁止混写:

| 类型 | 导向 | 回答的问题 | 写法要点 |
|---|---|---|---|
| Tutorial(教程) | 学习 | "带我做一遍" | 从零开始、每步可验证、保证成功 |
| How-to(操作指南) | 任务 | "怎么完成 X" | 前提条件 + 步骤清单 + 完成标准 |
| Reference(参考) | 信息 | "X 的准确定义/参数" | 表格化、无废话、可查阅 |
| Explanation(解释) | 理解 | "X 为什么是这样" | 讲原理、讲取舍、讲边界 |

判别法:混入了操作步骤的原理文 → 拆成 Explanation + How-to 两篇。

## 2. 知识层级(可迁移性测试)

frontmatter 中标注 `层级`,判定标准是"换掉 X 后这条知识还成立吗":

| 层级 | 判定 | 半衰期 |
|---|---|---|
| 原理层 | 换掉所有产品和模型仍成立(如 Transformer、Attention) | 5~10 年 |
| 模型层 | 换厂商成立,换模型代际部分失效(如 embedding、context window) | 1~3 年 |
| 范式层 | 不依赖具体工具(如 RAG、Agentic Search、CoVe) | 1~2 年 |
| 工具/生态层 | 依赖某工具但跨厂商(如 Chroma、MCP) | 半年~1 年 |
| 产品/厂商层 | 只对一家产品成立(如 AGENTS.md 路径规则) | 月级 |

范式层知识优先详写;产品层知识写"去哪查"而不是抄细节。

## 3. 写作规范

> **适用于所有笔记,无论概要级还是教材级**:两者的区别只在内容深度与研究投入(概要级短、不联网;教材级长、要研究),**写作质量标准完全相同**——不存在"概要级可以写得随便"。

- 结论先行:每篇第一屏给出核心结论,再展开
- 一段一个观点;短句;主动语态
- 每个概念至少配一个具体例子
- 术语约定:**英文原词(中文)**,首次出现加中文括号,如 hook(钩子)、chunking(切块);全库同一术语只用一种写法
- 关键事实必须标注来源:`[训练集]` / `[联网:链接]` / `[知识库:文件名]`;无法溯源的论断明确写"推断"
- 表格优先于大段罗列;对比类内容必须用表格
- **文章体,不是要点压缩体**:正文必须是完整的、能朗读出来的句子。箭头(→)、斜杠并列(如"session/harness/模型")、乘号(×)不得充当句子成分——它们只允许出现在表格、代码块和检查清单里。定义类句子先给场景或类比,再引出术语;不用多重括号叠加限定。自测:把这句话念出来,像不像人说的话
- **少用自造说法**:标准工程术语按三段式引入即可;但体系内部的口号、比喻、协议名首次出现必须跟一句大白话解释,能用平实句子说清的就不造新词。判断标准:没读过本知识库其他笔记的人能否看懂这句话
- **术语不堆砌,逐个交代**:一句话最多引入一个新术语/新缩写;多个术语并列时拆开写——每个配中文全称 + 一句"干嘛的"。多个标准术语挤在一句里造成的高密度,和自造词一样算违规;判断标准同上:没背过这些词的人能否读下去。
- **名字也要说明是什么**(同理,但出现较少):机构、产品、模型、工具、库/框架、协议、数据集等专有名词首次出现,跟一句"它是什么",如 Ai2(艾伦人工智能研究所,非营利研究机构);不留裸名。
- How-to(操作手册)必须**骨架-配方分离**:骨架写跨工具不变的步骤与完成标准;配方按 harness/环境分节并标注验证日期;只记本环境特有细节,通用命令不抄教程
- 操作手册与全库**共用同一术语约定**(英文原词(中文),如 skill(技能)、memory、hook),**禁止把常用术语翻译成中文别名**;但做**术语数量最小化**——只出现操作必需的术语,不引入理论侧术语(如幂等、append-only);白话体现在句式上:祈使句、命令可复制、每步给完成标志;原理只留 wikilink 不展开

## 4. 中文排版(《中文文案排版指北》要点)

- 中英文之间加空格:"使用 Chroma 存储",不写"使用Chroma存储"
- 中文语境用全角标点(,。;:),英文/代码内用半角
- 专有名词大小写正确:GitHub、LangChain、Obsidian,不写 github、langchain
- 数字与中文之间加空格:"3 个来源"

## 5. 结构与链接

- 文件命名:`前缀-NN-标题.md`,NN 两位数递增,标题不含空格
- 笔记正文骨架见 `assets/template.md`
- 每篇至少 1 个 [[wikilink]] 指向系列内其他笔记;文末"相关笔记"列出 2~3 个最相关链接
- 每次写入后必须更新系列 MOC(`XX-00` 索引):目录加条目、必要时 TL;DR 加一行、更新日期

## 6. 难度定标

> 以下规则**自足生效**,直接照条款执行,无需任何背景知识。风格拿不准时看同目录 `style-examples.md`(原文摘录 + 正/反写对照)。
> (出处:规则提炼自李博杰《深入理解 AI Agent》,全书开源——在线 https://bojieli.github.io/ai-agent-book/ ,GitHub https://github.com/bojieli/ai-agent-book ,可直接抓取章节深度校准。)
>
> ⚠️ 本规范有两套分层,勿混淆:**§2 可迁移性 5 层**(原理/模型/范式/工具/产品)用于 frontmatter 的 `层级` 字段与半衰期判断;**本节的 L0~L5 技术栈 6 层**只用于决定写多深。

- **读者画像**:正在动手搭系统的工程实践者,不是研究员
- **深度红线**:深在**工程机制与量化数字**(缓存、成本、延迟、可靠性取舍——影响动手决策的);**学术评测不进正文**(实验对照/消融表最多一句结论,出处放文末参考来源);数学只做直觉演算且放"可选,跳过不影响"框
  - 反例:"CoVe 四变体消融显示 factored 版将幻觉率从 X% 降到 Y%…(展开对照表)"
  - 正写:"CoVe 的关键是验证问题要**独立回答**,防止幻觉传染;实验细节见文末论文"
- **术语不设禁区,但必须三段式引入**:英文原词 + 中文括号 + 一句白话或生活类比(如"Circuit Breaker(熔断器)——像家里保险丝跳闸");类比可能失真时补一句"但要澄清"
- **结构节奏**:问题/场景/类比切入 → 给全篇地图 → 直觉 → 机制 → 金句收束;章末小结+自测题保留
- **证据形式**:关键论断配实证(实验/一手案例,失败过程也写);观点可引人;论文脚注化;反直觉论断必配适用边界("这一结论的设定是…")
- **学习范围定标(按 AI 技术栈 6 层:L0 数学 / L1 经典机器学习 / L2 深度学习 / L3 大模型 / L4 AI 工程与 Agent / L5 应用产品)**:
  - L0 数学:**术语级**——一句话讲"是什么、为什么需要它"(如"梯度下降——让模型往错得更少的方向调参数"),不展开
  - L1 经典 ML / L2 深度学习:**原理了解级**——术语 + 短段解释,能懂机制大意(如"上下文有限源于注意力的平方开销"),不推导、不实现
  - **L3 大模型 / L4 AI 工程与 Agent:深入区(优先)**——工程机制、量化取舍、实证
  - L5 应用/产品:**不深记**——操作性内容进操作手册(OPS 系列,骨架-配方);沉淀出的跨产品选型判断与模式上升为 L4 知识笔记
