# 风格样例(写作对照校准用)

> 用途:动笔前扫一眼找手感,写完抽一段对照自检。下面是一组"这样写 / 别这样写"的正反对照,自足可用。

## 一、正/反写对照(自检标尺)

**组 1|数据与实验不堆进正文**
- ✗ 反写:"CoVe 四变体消融实验显示,factored 版本将幻觉率从 X% 降至 Y%,joint 版本…(展开对照表)"
- ✓ 正写:"CoVe 的关键是验证问题要**独立回答**,防止幻觉传染;实验细节见文末来源。"

**组 2|术语三段式引入**
- ✗ 反写:"利用幂等性保证操作安全。"
- ✓ 正写:"脚本可以放心重复执行——同一操作跑多次结果不变,这个性质叫 idempotence(幂等)。"

**组 3|操作手册的白话句式**(术语保留,句式照做)
- ✗ 反写:"执行归档脚本以持久化会话转录。"
- ✓ 正写:"跑这条命令备份会话:`python3 skills/archive-sessions/scripts/archive_sessions.py` ✅ 看到 `x new/updated` 统计行就是成功。"

**组 4|开篇切入**
- ✗ 反写:"Query Routing 的定义是:根据查询特征选择知识来源的机制。"
- ✓ 正写:"你问 AI 一个问题,它该翻你的笔记、上网查,还是凭记忆答?这个'选路'动作就是 Query Routing(查询路由)。"

**组 5|术语堆砌:一句塞太多缩写(后训练场景)**
- ✗ 反写:"现在常用 DPO,老统称 RLHF;RL 算法有 PPO 和更省的 GRPO。"
- ✓ 正写(拆行,每个配全称 + 一句干嘛):
  - DPO(直接偏好优化):拿"人更喜欢 A 还是 B"的对比数据训练。
  - RLHF(基于人类反馈的强化学习):上面这类"从人反馈里学"做法的老统称。
  - PPO(近端策略优化)、GRPO(组相对策略优化):两种给奖励做训练的算法,GRPO 更省。

**组 6|术语堆砌:RAG 管线一口气念完**
- ✗ 反写:"chunking 后 embedding,存进 vector DB,查询先 recall 再 rerank。"
- ✓ 正写(拆步):
  - 把长文档切成小段(chunking,切块)。
  - 每段转成一串数字向量(embedding,嵌入)。
  - 存进向量数据库(vector database,向量库)。
  - 查询时先粗筛一批(recall,召回),再精排(rerank,重排)。

**组 7|单个术语也要配全称**
- ✗ 反写:"受 context window 限制,超了就截断。"
- ✓ 正写:"模型一次能读的文字量有上限,这个上限叫 context window(上下文窗口);超了会被截断。"

**组 8|名字要说明是什么(机构 / 工具库 / 模型)**
- ✗ 反写:"这套顺序就是 Ai2 的 Tülu 3 用的。"
- ✓ 正写:"这套顺序就是 Ai2(艾伦人工智能研究所)开源的 Tülu 3(它家模型 + 公开后训练配方)用的。"
- ✗ 反写:"用 vLLM 部署,本地拿 Ollama 拉起来。"
- ✓ 正写:"用 vLLM(高性能推理引擎,不是模型)部署;本地想快速跑就用 Ollama(在本机运行开源模型的工具)。"
- ✗ 反写:"换成 Qwen 或 Chroma 试试。"
- ✓ 正写:"换个模型试试,比如 Qwen(阿里开源大模型);或换向量库,比如 Chroma(一个向量数据库)。"

## 二、自检方法

1. 写完抽任意一段,自问:有没有日常锚点?句子是否够短?结论能否一句话复述?
2. 全文扫一遍,凡命中组 1~8 反写模式的,按正写改。
